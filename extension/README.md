# Obot — Chrome Extension

Chrome extension side panel for the Obot AI assistant. Connects to the Obot Workers backend and provides a chat interface with MCP plugin management.

## Stack

- **UI**: React 19
- **Build**: [WXT](https://wxt.dev) — modern extension framework (Vite-powered)
- **Styling**: Tailwind CSS v4 (tokens + scoped CSS)
- **Server state**: TanStack Query
- **Icons**: lucide-react
- **Agent SDK**: [`agents`](https://www.npmjs.com/package/agents) — `useAgent` WebSocket DO connection
- **AI Chat**: [`@cloudflare/ai-chat`](https://www.npmjs.com/package/@cloudflare/ai-chat) — `useAgentChat` hook
- **OAuth**: Google Identity (Chrome identity API)

## Architecture

### Agent connections

Two kinds of [Durable Object connections](https://developers.cloudflare.com/agents/) are used:

1. **`AgentProvider`** (`lib/agent.tsx`) opens **ONE** `UserAgent` connection per user (`useAgent`). This is the per-user DO that owns MCP plugin state. It exposes `addPlugin` / `removePlugin` and streams the live MCP server/tool/resource snapshot (`onMcpUpdate`) into `usePlugins()` context. The `PluginsScreen` uses this for MCP management.
2. **Each active thread** opens its **own** `UserAgent → ChatAgent` sub-agent connection via `useAgentChat` (`@cloudflare/ai-chat`). The ChatAgent DO hosts the conversation and tool execution for that thread.

### Typed messaging

`lib/messages.ts` defines the `ExtMessage` union that types all traffic between the side panel, the background service worker (`entrypoints/background.ts`), and the content script (`entrypoints/content.ts`) — e.g. `tabs:get`, `config:get`, `auth:signin`/`auth:signout`, `sidePanel:open`, plus tab broadcasts (`tab:activated`, `tab:updated`).

### Server-backed threads

Thread history lives on the worker, not just in local storage. `lib/api/threads.ts` (`listThreads`, `createThread`, `renameThread`, `deleteThread`) talks to `/api/threads` on the worker, and TanStack Query (`lib/query-client.ts` + `useThreads`) keeps the UI in sync. Unauthorized responses (401) clear auth automatically.

### Page context

Page-context extraction (headings, paragraphs, focused element) is consolidated in the content script via `lib/page-context.ts`. The side panel requests it with `requestPageContext` / `requestFocusedElement` (`lib/page-context-client.ts`); if the content script isn't injected on a page, it falls back to `chrome.scripting.executeScript` running the same extractor standalone.

## Development / Build

```bash
cd extension
npm install       # runs `wxt prepare` (postinstall)
npm run dev       # WXT dev server — loads the unpacked extension automatically
npm run build     # Production build → .output/chrome-mv3/
npm run zip       # Package the extension → .output/*.zip
npm run compile   # Typecheck (tsc --noEmit)
npm test          # Run Vitest
```

`WORKER_URL` (`lib/constants.ts`) resolves `import.meta.env.WXT_WORKER_URL` if set, otherwise defaults to:

- dev (`wxt`): `http://127.0.0.1:8787`
- build (`wxt build`): `https://api.linkos.in`

To point a build at a custom worker, set `WXT_WORKER_URL` in a local `.env` (see `.env.example`).

For local development, run the worker alongside on port `8787`:

```bash
# Terminal 1 — worker
cd worker && npm run dev    # wrangler dev on :8787

# Terminal 2 — extension
cd extension && npm run dev
```

## Load in Chrome

1. Run `npm run dev` (auto-loads unpacked), or `npm run build` first
2. Go to `chrome://extensions`
3. Enable **Developer mode**
4. Click **Load unpacked** → select the `extension/.output/chrome-mv3/` directory
5. Pin the Obot icon and click to open the side panel

## Authentication

Google ID-token sign-in via `chrome.identity.launchWebAuthFlow`. The extension requests `openid`, `email`, and `profile` scopes, then POSTs the ID token to `/api/auth/sign-in/social` on the worker (Better Auth). The user ID is used as the DO namespace for isolating MCP state.

## Manifest key

The extension ID stays stable across installs because `wxt.config.ts` preserves the public `key` from the original manifest — so the OAuth `client_id` registered for this extension keeps working after every rebuild.
